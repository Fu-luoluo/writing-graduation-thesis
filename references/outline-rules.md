## 1. 标准结构

综述类毕业论文的标准结构（允许优化，不得随意推翻）：

```
摘要 / 关键词
1 引言
2 技术演进脉络
3 研究现状
4 大模型/关键技术专题研究进展
5 核心挑战
6 未来发展趋势
7 结论
参考文献
```

## 2. 调整原则

1. 以草稿现有结构为基础，合理观点与结构予以保留；
2. 调整标题层级或合并章节时，必须先给出"**原大纲问题—调整方案—调整理由**"，并在格式检查报告中列出调整对照表；
3. 章节之间须明确分工、合并去重，避免同一主题在多章重复；
4. 第 5 章挑战、第 6 章趋势须与第 2—4 章的问题一一呼应，避免空泛；
5. 调整后的大纲在闸门 1 提交用户确认后，才进入正文写作。

## 3. 各章分工

| 章节 | 职责 | 边界 |
|---|---|---|
| 1 引言 | 研究背景与意义、研究范围与方法、相关研究概况 | 不展开具体技术细节 |
| 2 技术演进脉络 | 按"感知—通信—交互（或计算）"主线梳理技术阶段演进 | 只讲"如何发展而来"，不做现状分类 |
| 3 研究现状 | 按系统形态/技术路线分类总结代表研究与局限 | 只讲"当前有哪些方案"，不重复演进史 |
| 4 专题研究进展 | 聚焦关键技术（如大模型语音交互）的原理、赋能与空白 | 不重复第 2 章的交互演进 |
| 5 核心挑战 | 按感知/交互/架构/应用分层提炼问题 | 每条问题对应前文具体研究 |
| 6 未来趋势 | 针对挑战给出研究方向 | 与第 5 章一一对应 |
| 7 结论 | 总结全文，指出研究空白与意义 | 不引入新文献、新观点 |

## 4. 提纲式写法处理

1. 项目符号、提纲标签（"现实背景：""技术背景：""优势与局限："等）必须改写为连贯学术段落；
2. "技术方案—代表研究—优势与局限"可作为段落内逻辑顺序，但不得写成固定标签；
3. 段落之间需有过渡与评述，避免文献简单罗列；
4. 全文术语统一，使用学术语气，消除口语化、宣传化表达。

## 5. 摘要与关键词

1. 摘要压缩至 250—300 字，按"背景与问题—本文工作—结论与意义"组织；
2. 关键词精简为 3—5 个，分号分隔；
3. 摘要不出现引用编号、不出现图表编号。

## 6. 典型问题与处置

| 草稿典型问题 | 处置 |
|---|---|
| 摘要偏长（如 300 字以上） | 重写压缩至 250—300 字 |
| 关键词偏多（6 个以上） | 精简为 3—5 个最核心主题 |
| 引言各小节为短句罗列 | 改写为完整学术段落 |
| 演进章与专题章内容交叉 | 明确分工：演进章讲阶段史，专题章讲原理与空白，重复部分合并 |
| "优势与局限"写法机械 | 保留为段落内逻辑，去除固定标签 |
| 挑战/趋势空泛 | 与前文具体问题逐条呼应 |
